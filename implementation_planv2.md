# FlowForge Architecture & Implementation Blueprint (Single Source of Truth)

This is the definitive master plan for the FlowForge modernization project. As this is a **DevOps training project**, the goal is to demonstrate robust cloud architecture and RBAC principles without overcomplicating the setup with unnecessary enterprise-grade overhead.

We will leverage the existing dashboard components wherever possible, simply reorganizing them to fit the new strict role boundaries.

---

## 1. Execution Strategy & Phased Approach

To ensure smooth development, we will build and test the application logic locally first, saving the complex infrastructure and identity migrations for the end.

### Phase 1: Application Logic & Dashboards (Local Docker Compose)
We will develop and test all RBAC shifts, dashboard reorganizations, and PDF generation logic locally using `docker-compose`. 
**Required Azure Resources for Phase 1:**
To test the app locally, we must provision the following Azure resources upfront:
- **Azure AI Foundry**: Deploy the `gpt-35-turbo` model so the `analysis-service` can generate summaries locally.
- **Azure Storage Account**: Create a Blob container (`flowforge-reports`) so the local app can upload and fetch generated PDFs.
*(Note: We will use local `.env` files for secrets during this phase instead of Key Vault).*

### Phase 2: Entra ID Authentication Integration
**As requested, this will be done LAST on the application side.** Once all dashboards and reporting features are working perfectly with the current local email/password system, we will rip out the local auth and replace it with Azure Entra ID SSO and Microsoft Graph API B2B guest invites.

### Phase 3: Azure Infrastructure Migration
Once the app works locally with Entra ID, we will deploy the final Azure infrastructure (AKS, App Gateway, Front Door, Key Vault) and migrate the application to the cloud.

## 2. Strict Dashboard Separation & Scopes

We will reuse existing components/charts and simply move them to enforce a strict separation of concerns.

### Platform Admin Dashboard (System Intelligence)
*Scope: Platform side only (Infrastructure & Costs).*
- **Existing AI Cost Monitoring**: Let it be exactly as it is.
- **System Analytics Tab**:
  - **Metric Cards**: Total Platform Users, Active vs. Inactive User Ratios.
  - **Health Cards**: Live "Connected" / "Not Connected" status for the Database and Redis.
  - **Connection Latency Graph**: A line graph plotting Ping Latency (in milliseconds) for the Database and Redis connections.

### Org Owner Dashboard (Business Intelligence)
*Scope: Organization side only (Tasks, Projects, Team).*
- **Transferred Analytics**: All business metrics currently in the Platform Admin dashboard will be moved here.
  - **Metric Cards**: Total Tasks, Active Projects, Team Members, Overall Completion Rate.
  - **Task Throughput Bar Graph**: Shows tasks completed over time.
  - **Task Status Distribution Pie Chart**: Shows the breakdown of TODO, IN_PROGRESS, and DONE.

### Manager Dashboard
- **Metric Cards**: Number of Team Members, Members Assigned to Tasks, Members Not Assigned.
- **Team List**: Shows all members assigned to this manager, with a column indicating their current "Project Name" (or blank if unassigned).
- **Project List**: Organized by tabs: **Active**, **Archive**, and **All**.

### Universal UI Changes
- A **"Refresh" button** will be added to the header of all roles.

## 3. Professional PDF Reporting & Blob Storage

The AI Summary feature is an exclusive reporting engine for the organization's leadership.

### Exclusive to Org Owner
**The "Reports" feature will ONLY be available to the Org Owner.** Managers will not have access to this page or the generation buttons.

### The UI Workflow & Document Viewer
1. **Reports Page**: A dedicated page in the sidebar for the Org Owner listing all historically generated reports.
2. **Overlay Document Viewer**: When the Org Owner clicks "View" on a report, the PDF is fetched from Azure Blob Storage via a SAS URL and rendered inside a sleek **modal overlay (Doc Viewer)** directly within the dashboard. It does not open a new tab.
3. **Project List Integration**: Org Owners will see "Generate & View" or "Download" buttons directly on the projects list.

### The PDF Structure
The `analysis-service` will generate a professional PDF containing:
1. **Header**: FlowForge branding, Report Title, and Timestamp.
2. **AI Executive Summary**: The narrative generated by `gpt-35-turbo`.
3. **Visual Metrics**: Embedded charts mapping the Task Status distribution and throughput.
4. **Team Performance Breakdown**: A detailed list of Managers and the users assigned under them, specifically showing the number of tasks completed and their current status breakdown.

## 4. Authentication & IAM (Phase 2 Details)

When we implement Entra ID in Phase 2, the workflow will be:
- **Login**: Users click "Login with Microsoft". They are not asked to create a new password. They use their existing email to authenticate. FlowForge reads their Security Group from the token.
- **Invite**: The Org Owner invites users via the FlowForge UI. The backend uses the Microsoft Graph API to send an Entra ID B2B Guest Invitation and assigns them to the correct Security Group.
- **Revoke**: The Org Owner clicks "Revoke". Locally, `is_active = false` (they get a "Revoked" badge in the UI). In Azure, the Graph API removes them from the Security Group, instantly revoking login access.
- **Re-Enable**: Clicking "Re-Enable" sets `is_active = true` and adds them back to the Azure Security Group.

---

## 5. Final Azure Cloud Integration (Phase 3 Details)

1. **Global Routing**: Azure Front Door (Standard) configured with `flowforge.fun` for SSL and routing.
2. **Ingress**: Azure Application Gateway + AGIC deployed in a VNet, routing traffic to AKS pods.
3. **Compute**: Azure Kubernetes Service (AKS) hosting all microservices.
4. **Secret Management**: Azure Key Vault integrated with the AKS Secret Store CSI Driver to securely mount secrets as volumes.
5. **Databases**: Azure PostgreSQL Flexible Server and Azure Cache for Redis.
